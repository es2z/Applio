# 男性 → 女性変換を改善する候補案

2026-11-25 にユーザーと検討した案の一覧と、順位の理由。いま実装を進めているのは案 1 で、計画は
`docs/PLAN-source-matched-training.md` にある。ここにあるのはそれ以外の案と、検討の経緯。

前提（2026-11-25 時点）:
- ソースはユーザー（男性）、ターゲットは naru。推論時のピッチ +12.3〜12.7 半音。
- naru モデルは kushinada L24（`naru_20261027` 系）。SPIN v2 は embedder としては不採用（声がこもる）で、
  key index の検索キーとしてだけ使っている（CLAUDE.md の SPIN 節、`logs/_spin/RESULTS.md` 16, 18-21）。
- リアルタイムは 1080 ms ブロック、処理 p50 は 40〜60 ms 程度。
- Seed-VC などへの乗り換えは後回し（本家 RVC から多くの改良を入れているため。ユーザー判断、2026-11-25）。

## 見送った案: embedder にピッチ・フォルマント変更音声を追加学習

ユーザーの最初の発想は「通常の音声・ピッチ変更・ピッチ + フォルマント変更の音声を embedder に追加学習させ、
入力音声もピッチとフォルマントを変更したものにする」だった。

見送った理由: SPIN の摂動（Praat の "Change gender" = ピッチ + フォルマント変更、+ ランダム EQ）がほぼこれで、
その結果、特徴量からスペクトルの細部が落ち、本学習した声がこもった（ridge probe で log-mel の R² が
L24 0.788 → SPIN 0.724〜0.745、`RESULTS.md` 16）。フォルマント変化に不変になるよう学習すること自体が、
スペクトル情報を捨てることになっている可能性が高い。

同じ拡張を **embedder ではなく RVC モデルの入力側だけ** に入れれば、embedder の細部は保ったまま、モデルに
不変性を学ばせられる。これが案 1 と 1b。FreeVC が同じ考え方で、スペクトログラムを縦方向に伸縮する
データ拡張を、内容エンコーダへの入力側だけにかけて、内容情報から話者情報を減らしている。

推論時に入力のフォルマントを変える方は、学習時にモデルがその加工を一度も見ていないと、加工音そのものが
見たことのない入力になる。ユーザーが試して不採用にしたのはおそらくこのため。案 1b の加工を学習時にも
入れるなら、再検討の余地はある。

## 案 1b: Praat で男性側に下げた naru 音声の特徴量で学習する

案 1（`docs/PLAN-source-matched-training.md`）の「ユーザーモデルで変換した音声」の代わりに、
`tools/spin/perturb.py`（Praat の "Change gender"）で naru の音声を男性側へ動かしたものを使う。

- 目安: フォルマント比 0.8〜0.9、F0 中央値比 約 0.5（naru の F0 をユーザーの音域へ）。範囲内でランダムにする。
- 利点: ユーザーモデルが不要で、すぐ作れる。CLAUDE.md の SPIN 節で "Not tried yet" として残っていた案
  （naru 自身の音声を摂動し、元の音声を正解にする）の、方向を男性側に絞ったもの。
- 欠点: 特定のソース（ユーザー）には寄らない。Praat の性別変換の音質が、そのまま入力の癖になる。
- 実装: 案 1 の学習側（`srcaug_prob`）をそのまま使える。特徴量を作るスクリプトだけ別に用意すればよい
  （`extracted_srcaug/` の manifest に生成方法を記録する）。案 1 と 1b を混ぜる場合は、ディレクトリを
  分けて確率を別々に持たせる拡張が必要。

## 案 2: 特徴量の写像

ユーザーの特徴量を naru の特徴量へ写す関数を、index 検索・モデル入力の前に挟む。

- **LinearVC**（Kamper ら、Interspeech 2025）: 自己教師あり特徴量の線形変換だけで声質変換ができ、
  回転だけに制約しても高品質だった。ソースとターゲットのフレームを最近傍で組にして線形写像を学習している。
  https://arxiv.org/abs/2506.01510 / https://github.com/kamperh/linearvc
- **SSL-GMMVC**（田名部ら、東大、Interspeech 2026）: LinearVC の単一の写像を、GMM による局所線形変換の重み付き和に
  置き換えたもの。話者類似度が上がり、明瞭性と自然さは同程度だった。 https://arxiv.org/abs/2606.10317
- **最小版: 平均の差だけ足す。** `feats += a * (mean_naru - mean_user)`。WavLM 第 6 層では、発話平均の特徴量の
  主成分 1（分散最大）が平均ピッチ・性別と最も強く相関し、その方向に動かすと音高が約 100 Hz から 300 Hz まで
  変わった（arXiv 2603.03096）。kushinada L24 でも同じかは未測定。
  https://arxiv.org/html/2603.03096

学習データ: 案 1 で作る `extracted_srcaug/`（ユーザー風）と `extracted/`（naru）は、**フレーム単位で揃った
パラレルデータ**なので、最近傍で組を作る必要もない。案 1 の副産物として、ほぼ無料で試せる。

注意:
- RVC の index ブレンドは、実質的にノンパラメトリックな写像（kNN-VC と同じ考え方）。写像はそれをパラメトリックにした
  もので、置き換えるのか、index の検索キーを改善するのか（写像後に検索）、両方試す価値がある。
- 写像した特徴量でモデルを学習していないので、写像の出力がモデルにとって見慣れない分布になる可能性がある。
  index_rate と同じように、元の特徴量との混合率で効き具合を調整する。
- 評価は key index と同じ物差し（held-out の PER、naru 方向へのシフト、`rt_rate_sweep.py`）で比べる。
- リアルタイム: 1024×1024 の行列演算 1 回程度。key index の +10 ms と比べれば無視できる。

## 案 3: F0 の分布を合わせる

今は一定量（+12.3〜12.7 半音）ずらしているだけで、抑揚の幅（対数 F0 の分散）はユーザーのまま。

- 変換: `log f0_out = mu_naru + (sigma_naru / sigma_user) * (log f0_in - mu_user)`（有声フレームのみ）。
  mu, sigma は naru の `f0_voiced/*.npy` とユーザーの学習データから事前に計算する。固定値なのでリアルタイムでも使える。
- 合わせて確認すること: 変換後の F0 のうち、naru の学習データの音域から外れるフレームの割合。音域外の F0 は
  モデルが学習していないので、かすれや歪みの原因になる。歌声変換の SPA-SVC（Interspeech 2024）は、ソースの音高が
  ターゲットの音域から大きく外れるとかすれた音になることを報告し、6〜18 半音の大きなピッチ拡張で対処している。
  https://arxiv.org/abs/2406.05692
- Applio の既存機能 `proposed_pitch` は平均を合わせるもので、分散は合わせない。
- 注意: sigma 比を 1 より大きくすると抑揚が誇張され、F0 推定の誤り（オクターブ誤り）も増幅される。
  比は 1.0〜1.3 程度から聴いて決める。

## 後回し: 方式ごと乗り換える候補

いまの RVC 構成（独自の vocoder、F0、embedder、key index、リアルタイム改修）を捨てることになるので後回し。
比較する日のためのメモ。

- **Seed-VC**（GPL-3.0）: 拡散トランスフォーマ。参照音声を丸ごと文脈として使い（in-context learning）、学習中は
  外部の声質変換器で入力側の声質を崩して、ソースの声質が漏れないようにしている。ターゲット話者の音声だけで
  追加学習（ファインチューニング）でき、最小 1 発話・100 ステップから。追加学習すると話者類似度は上がるが、
  WER はやや悪化しうる。リアルタイムは合計約 430 ms（アルゴリズム約 380 ms + 機器約 100 ms）。
  Applio で学習したモデルとは互換性がなく、学習も推論も Seed-VC 側のツールで行う。
  https://github.com/Plachtaa/seed-vc / https://arxiv.org/abs/2411.09943
  - 遅延について: RVC も 1080 ms のブロックが溜まってから変換するので、今も 1 秒程度は遅れていると考えられる。
    ただしブロックの重ね合わせ等で実際の遅延は短い可能性があるので、比べるなら実測すること。
- **Beatrice 2**（MIT）: ReazonSpeech で学習しており日本語に強く、遅延 50 ms 未満。ターゲット話者ごとに学習する。
  https://huggingface.co/fierce-cats/beatrice-trainer
- **MeanVC 2**（2026-06）: ストリーミングのゼロショット VC で、エンドツーエンド 110 ms。学習データが中国語・英語中心なので、
  日本語の品質は未知数。 https://huggingface.co/ASLP-lab/MeanVC2

## 参考: 関連する手法

- **kNN-VC** の prematched vocoder: 学習時に、各発話の特徴量を同じ話者の他の発話から kNN で組み直したもので
  vocoder を学習し、推論時の入力に近い条件で学習させる。明瞭性と話者類似度が上がった。
  RVC で言えば「index で置き換えた後の特徴量で学習する」に相当し、案 1 とは別の軸の「学習と推論のずれ」を埋める案。
  https://arxiv.org/abs/2305.18975
- **FreeVC** の spectrogram-resize 拡張: https://arxiv.org/abs/2210.15418
