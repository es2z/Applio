# 事前学習と本番学習の手順（手で行うこと）

Applio の学習タブで手で行う操作と、推奨値の一覧。
データの点検・加工（無音の切り詰め、バイノーラルの処理など）は Claude に頼む。手順は [dataset-prep-for-claude.md](dataset-prep-for-claude.md)。

2026-10-03 時点の推奨。SiFi-GAN+ の音質は、まだ A/B 比較で確かめていない。

## 全体の流れ

```
段階1 事前学習   : いろいろな話者のデータ（数時間） → 土台になる G/D を作る（変換には使わない）
段階2 本番の学習 : 学習したい人の 20〜30 分        → 段階1 の G/D から学習する（変換にはこれを使う）
```

段階 1 と 2 で**そろえる設定**: サンプリング周波数、ボコーダー（と SiFi-GAN のフィルタブロック）、embedder、Embedder Output Layer、F0 手法、F0 Coarse Range、Normalization、データの加工方法（`--stereo louder` など）。
どれかがずれると、引き継げない部分が出るか、学習した条件と違うデータで仕上げることになる。

## データのフォルダ構成

**段階 1（事前学習）**
```
temp\                 ← 元データ（Claude はここを読むだけで変更しない）
├── 0\   本番の声のうち、音色で選んだもの（本番と同じ 23 分など）
├── 1\   本番の声の残り（調子がいまいちな部分）
├── 2\   ほかの話者（ITA の 1 人目）
├── 3\   ほかの話者
└── ...
```
- フォルダ名は **0 から始まる連番の数字**にする。数字でないフォルダは、前処理が黙って読み飛ばす。
- 直下にファイルを置かない。置くと話者 0 に混ざる。
- 1 人 1 番号にする。感情やスタイルの違いでは分けない。例外は、声の調子のように声質そのものが違い、それぞれ十分な量（目安は数十分以上）がある場合。
- 音割れ、強いノイズ、強い響き、BGM 入りの録音は入れない。「声の調子がいまいち」なのは入れてよい。
- 評価（聴き比べや A/B）に使う音声は、段階 1 にも段階 2 にも入れずに取っておく。

**段階 2（本番）**: 学習したい人の音声を、サブフォルダなしで 1 つのフォルダに入れる。自動で話者 0 になる。

## 準備（Claude に頼む）
1. 「`temp` を点検して」→ 問題点の報告を受け、必要ならデータを作り直す。
2. 「`temp` から `temp2` を作って」→ 無音の切り詰めと、ステレオの処理をしたコピーができる。
3. 本番の声のデータにも、同じ加工をしてもらう（バイノーラルなら `--stereo louder`）。

## 段階 1: 事前学習の設定

**モデル設定**
| 項目 | 推奨 | 理由 |
|---|---|---|
| Model Name | 新しい名前（例: `pretrain_ita_sifiganplus`） | |
| Sampling Rate | 48000 | |
| Vocoder | SiFi-GAN+（または本番で使うもの） | 本番と同じにする |
| SiFi-GAN Filter Blocks | **rvc** | HiFi-GAN から引き継げる量が多い（rvc 約 75%、official 約 62%）。これまでの実測はすべて rvc。official を選ぶなら本番も official |
| SiFi-GAN Source Gain | 0.03 | 既定値。HiFi-GAN から引き継ぐ場合の最適値として実測したもの |

**前処理（Preprocess）**
| 項目 | 推奨 | 理由 |
|---|---|---|
| Dataset Path | `C:\dev\myapplio2\temp2` を**欄に直接入力** | 一覧には `...\0`、`...\1` が別々に出る。選ぶとその 1 人分しか学習されない |
| Audio cutting | Automatic | 長い無音は前処理自身が捨てる |
| Noise filter | ON（既定） | 48 Hz のハイパスで、ノイズ除去ではない |
| Noise Reduction | OFF | ノイズが無ければ不要。かけると不自然な音が混ざる |
| Normalization mode | **pre** | ファイル単位で音量をそろえる。話者間で 15 dB ほど差があった。post は 3 秒の断片ごとにそろえるので、弱い語尾まで持ち上がる |

**特徴抽出（Extract）**
| 項目 | 推奨 | 理由 |
|---|---|---|
| Pitch extraction algorithm | HPA-RMVPE (112000, aligned) | gaps filled を学習に使うとノイズが増えた経験があるため |
| Embedder | kushinada-hubert-large | |
| Embedder Output Layer | 0（最終層） | 既存モデルと同じ |
| Silent training files | 2（既定） | 無音を学習させるためのサンプル |
| F0 Coarse Range (Hz) | 1100 | 1100 Hz を超える声（歌の高音など）が無ければ十分。範囲を変えても出力のピッチの精度は変わらない（細かい F0 は別経路で渡る） |

**学習（Train）**
| 項目 | 推奨 | 理由 |
|---|---|---|
| Batch Size | 24 | このカードではバッチを下げると時間あたりの学習が遅くなる（実測） |
| Cache Dataset in GPU | OFF | 数時間分はキャッシュに 1 秒あたり約 1 MB 必要で、24 GB に収まらない。SiFi-GAN+ は 1 ステップが重いので、キャッシュが無くても遅くならない |
| Total Epoch | 500（既定）でよい | 途中で止めてよい。学習率の減衰はエポック単位なので、総数は学習内容に影響しない |
| Pretrained / Custom Pretrained | 両方 ON | 下の「引き継ぎ元」を参照 |
| Overtraining Detector | OFF | 事前学習では不要 |
| Learning Rate / Mel Loss Weight / Learning Rate Decay | 1e-4 / 45 / 0.999875（既定） | SiFi-GAN 系の mel は HiFi-GAN と別の関数（マルチスケール）なので、HiFi-GAN で使っていた 48 などの値は流用しない |
| Initial Generator LR Boost | OFF | 1 エポックが長いので、既定の 10 エポックでも数千ステップ、引き継いだ部分まで 3 倍の学習率で動かすことになる |
| 重みを引き継いで学習をリセット | **使わない** | 同じフォルダの G/D を引き継ぐ機能で、新しいフォルダでは止まる |
| Index | 気にしなくてよい | 学習後に自動で作られるが、事前学習では使わない |

**保存の設定（バッチサイズの下）**
| 項目 | 推奨 | 理由 |
|---|---|---|
| RVCモデルの保存間隔 | 5 前後 | 15 分に 1 回程度。再開用の G/D（最新を上書き）と TensorBoard の音声もこの間隔 |
| RVCモデルを毎回残す | ON | 途中経過を聴いて確認するため（1 回約 80 MB） |
| G/D も残す（× n） | OFF | ベストの G/D があれば足りる。決まった間隔の G/D も欲しいときだけ |
| 評価が良い上位を保存する | **ON** | 音質はチェックポイントごとに 20〜25% 揺れる。最後の1つより途中の良い1つの方が良いことがある |
| 残すもの | 重みと G/D の両方 | G/D は段階 2 の引き継ぎ元に使える（1 組約 0.5 GB） |
| 残す数 | 3 | |
| 評価のタイミング | 保存時 | 評価は数秒で済む |
| ベストの基準 | combined | mel とノイズっぽさの両方を見る |
| 評価セット | 下の「評価セットの作り方」で作ったもの | 同じセットを段階 1・2 と A/B の両方で使うと、数字を比べられる |

**評価セットの作り方**
1. 「評価が良い上位を保存する」を ON にすると出る「新しい評価セット」に名前を入れて [作成] を押し、[フォルダを開く] で開く。中の readme.txt に、どこに何を入れるかが書いてある。
2. `trained\<話者番号>\` に、学習データに入っている音声（元音声のコピー）を話者ごとに数本入れる。
3. `heldout\<話者番号>\` に、学習データに入れていない同じ話者の音声を入れる。**事前学習・本番の両方のデータから外しておく。** 無ければ空でよい。
4. `convert\` に、別人の声を数本入れる。
5. [更新] を押して選び、中身の要約で本数を確かめる。

**できあがるもの（チェックポイント）**: `logs\<モデル名>\checkpoints\best\` に、上位の書き出しモデルと G/D（`G_<エポック>e.pth` / `D_<エポック>e.pth`）。順位とスコアは `checkpoints\state.json` と TensorBoard の `eval/` にある。

**引き継ぎ元（Custom Pretrained G / D）**
- 欄にパスを直接入力する。一覧に出るのは `rvc\models\pretraineds\custom` の中だけ。
- 使うのは学習フォルダの `G_*.pth` / `D_*.pth`。書き出しモデル（`<名前>_XXXe_YYYs.pth`）は使えない。
- 古いチェックポイント（例: `naru_20260906_kushinada_hubert_large_test1`）は F0 範囲の記録が無い。**Claude に記録を補ったコピーを作ってもらい、それを指定する。**
- SiFi-GAN の official と rvc の間は引き継げない。HiFi-GAN の G/D からなら、どちらにも引き継げる。

**学習開始時のログで確認すること**
- `Warm start (G)` / `Warm start (D)` の inherited の割合。HiFi-GAN → SiFi-GAN+ (rvc) なら、G 約 75%、D 99.4% が目安。
- `Training recipe SiFi-GAN+: the SiFi-GAN generator against discriminator v3-48k` が出ていること。

**できあがるもの**: `logs\<モデル名>\G_2333333.pth` と `D_2333333.pth`。これが段階 2 の引き継ぎ元になる。
ベストを残していれば、`checkpoints\best\G_<エポック>e.pth` / `D_<エポック>e.pth` のうち聴いて良かったものを使ってもよい。

## 段階 2: 本番の学習

段階 1 と同じ設定にする。違うところだけ書く。
| 項目 | 設定 |
|---|---|
| Model Name | 本番用の新しい名前 |
| Dataset Path | 本番の声を加工したフォルダ（サブフォルダなし） |
| Custom Pretrained G / D | 段階 1 の `logs\<事前学習の名前>\G_2333333.pth` / `D_2333333.pth`（または `checkpoints\best\` の G/D） |
| Overtraining Detector | 好みで |
| 評価セット | 段階 1 と同じもの。話者が1人の学習なので、番号に関係なくすべて話者 0 として評価される |
| 残す数 | 3〜5。止めどきは、学習データの mel ではなく `eval/B_mel`（heldout）と `eval/C_noise` が悪くなり始めたところ |

開始時の `Warm start (G)` / `Warm start (D)` が 100% 近くなっていれば、設定がそろっている。大きく下がっていたら、そろえる設定のどれかがずれている。

## 目安
- **ディスク**:
  - 前処理と特徴抽出で、学習音声 1 秒あたり約 0.9 MB（5 時間で約 16 GB）。
  - チェックポイントは保存 1 回約 1.1 GB、書き出しモデルは約 80 MB。
- **速度と VRAM**: SiFi-GAN+ はバッチ 24 で 1 ステップ約 0.57 秒（RTX 4090、fp16）。VRAM はキャッシュなしで約 16.3 GiB（42 分のデータをキャッシュした実測で 19.4 GiB、うちキャッシュが 3 GiB）。
- **1 エポック**: 断片の数 ÷ バッチのステップ数になる。断片は前処理で 3 秒以下に切られる（平均 2 秒前後）。
