# F0推定方式の測定メモ（2026-09-28〜29）

このフォークで使えるF0推定方式を、同じ条件で測った結果をまとめたものです。
個々の方式の詳細は [fcn-993.md](fcn-993.md)、[fcn-929.md](fcn-929.md)、
[fcnf0pp.md](fcnf0pp.md)、[hpa-rmvpe.md](hpa-rmvpe.md) を参照してください。

**共通の条件**

- 環境：RTX 4090、PyTorch 2.13.0+cu132。
- 経路：通常推論と同じ `Pipeline.get_f0` を通しています（`tools/compare_f0_methods.py` の `extract`）。
- モデルのcoarse範囲は1680 Hzです。そのため、CREPE系などのF0探索範囲も50〜1680 Hzになります。
- mangio-crepeのデコーダーは既定のviterbiです。viterbiは実行ごとに結果が少し揺れます（最大20〜30 cent程度）。
- FCN-929-RVCとFCN-993-RVCは、同梱の標準設定（Balanced v1）です。

## 3. SwiftF0（`swift`）の組み込み方の問題（未修正）

`rvc/lib/predictors/f0.py:206` の組み込み方に、2つの問題があります。

1. 16 msごとの推定値を、無声を0 Hzとしたまま線形補間しています。有声/無声の境目に架空の中間値が生まれ、
   `reference.wav` では124フレームが600 cent以上外れていました。
2. 時刻が合っていません。RVCのフレームkは k×10 msですが、k×10+5 msの位置を読んでいます
   （ライブラリの時刻はフレーム中心）。それとは別に、出力はRMVPEに対して遅れていて、
   下の表では15 msの補正が最良でした。

組み込み方だけを変えて、1節と同じ正解付き4音声で比べた結果です。

| 版 | 無声→有声の誤り | 有声→無声の誤り | RPA50 | RPA25 | 中央値 |
|---|---:|---:|---:|---:|---:|
| 現状 | 57/479 | 39/804 | 75.0% | 55.5% | 19.3 |
| 境目の補間を修正（+5 msのまま） | 26/479 | 60/804 | 77.4% | 57.0% | 17.8 |
| 上に加えて、格子を k×10 ms に | 37/479 | 65/804 | 66.7% | 46.1% | 24.9 |
| 上に加えて、10 msの遅れを補正 | 31/479 | 58/804 | 83.5% | 68.7% | 12.3 |
| 上に加えて、**15 msの遅れを補正** | 28/479 | 62/804 | **85.1%** | **74.9%** | **9.2** |
| 上に加えて、20 msの遅れを補正 | 40/479 | 67/804 | 83.1% | 71.6% | 9.8 |
| rmvpe（参考） | 83/479 | 9/804 | 91.8% | 81.5% | 8.0 |

修正しても声の取りこぼしが多く、rmvpeには届きません。**Realtimeタブの既定のF0方式はこの `swift` です。**

## 5. realtimeの明瞭度の調査

「realtimeでRMVPEを使うと、FCNより発音が曖昧に聞こえる」という問題を調べた記録です。

**対象モデル**：`naru_20260926_deka_MRF_kushinada_1024_FCN993RVC_data5_1`（1400e／1860e）。
MRF HiFi-GAN、kushinada-hubert-large、coarse 1680 Hzで、F0は **FCN-993-RVC（enter 0.3 / exit 0 / median 3）** で学習しています。

**realtimeの設定**：テンプレートと同じく、ブロック960 ms、extra 0.22 s、crossfade 0.138 s、index 0.8、protect 0 です。
入力は学習話者の日本語音声（約44秒）で、ピッチは0です。

### 5.1 有声/無声の扱い

| 項目 | 値 |
|---|---|
| 学習データのF0：発話中の有声率 | 99.48% |
| 学習データのF0：有声区間の途中で無声になったフレーム | 0 |
| 44秒の音声での有声/無声の切り替え回数 | RMVPE 209回 / FCN（0.3/0/0）0回 / FCN Balanced v1 304回 |

exit 0では、一度有声になると完全な無音まで有声が続きます。
そのためこのモデルは、発話の途中で「F0 = 0」になる入力を学習中に一度も見ていません。

### 5.2 子音部分のF0

RMVPEが無声とした部分を「子音・息の部分」とみなして比べました。

| | 母音部分（RMVPEが有声） | 子音・息の部分（RMVPEが無声） |
|---|---|---|
| FCNの信頼度（中央値） | 0.88 | 0.28 |
| FCN（0.3/0/3）で、隣のフレームとF0が300 cent以上飛ぶ割合 | 0.5% | **26.3%** |
| RMVPE（隙間を補間）で、同じく300 cent以上飛ぶ割合 | 0.1% | 0.0% |

両方が有声の部分では、FCNとRMVPEのF0の差は中央値6.2 centでした。

### 5.3 聞き比べ（realtime処理で作成、1860e）

| 版 | 内容 | ユーザーの聴感 |
|---|---|---|
| A | RMVPEそのまま | 最も曖昧 |
| B | RMVPEの無声の隙間を、前後のF0の対数補間で埋めたもの（常に有声） | Aより約40%改善 |
| C | FCN-993-RVC（0.3/0/3） | 最もはっきり。ただし雑音のようなものが多い |
| D | FCNのF0に、RMVPEが無声とした区間だけを持ち込んだもの | （未評価） |

### 5.4 参考：音素認識による測定

日本語の音素認識モデル（prj-beatrice/japanese-hubert-base-phoneme-ctc-v4）で、入力の認識結果に対する音素誤り率を測りました（1860e）。
**「正しく認識できるか」の指標で、聞こえ方の曖昧さは測れていません。**

| 条件 | 音素誤り率 |
|---|---:|
| 通常推論：rmvpe / fcn-993-rvc / fcn-929-rvc | 21.4% / 20.8% / 20.5% |
| realtime：rmvpe | 29.6% |
| realtime：rmvpe（修正前のcoarse式を再現） | 30.5% |
| realtime：fcn-993-rvc（0.3/0/0） / fcn-929-rvc | 34.3% / 34.3% |
| realtime：protect 0.5（rmvpe / fcn-993-rvc） | 30.8% / 33.4% |
| realtime：extra 0.5 s（rmvpe / fcn-993-rvc） | 33.1% / 35.8% |
| realtime：extra 1.0 s（rmvpe / fcn-993-rvc） | 35.2% / 35.5% |

realtimeで出力に使われたF0を、同じ方式で音声全体を見て求めたF0と比べると、次のようになりました。

- rmvpe：有声/無声の不一致5.6%、差の中央値14.5 cent、50 cent超が10.2%
- FCN：0%

rmvpeは、先の音を見ずにF0を決めているためです。

### 5.5 解釈

- 学習時と変換時で、有声/無声の与え方が違います。RMVPEは、子音で学習外の「F0 = 0」を出します。
  そこでは音源が正弦波から雑音に、ピッチ埋め込みが無声の番号に、protect 0のため特徴量が元の声に、それぞれ切り替わります。これがAの曖昧さの主因と考えられます。Bの改善がその裏付けです。
- このモデルは、FCNが子音で出す「荒れたF0」を子音の目印として学習しています。Bの子音部分はなめらかなので、Cほどはっきりしません。
  Cの雑音も、同じ荒れたF0で音源の高さが飛ぶことで説明できます。
- 改善の方向：
  1. 有声/無声の判定がある設定（例：Balanced v1）でF0を抽出し直して学習し直す（弱い声が途切れる可能性あり）
  2. 常に有声で学習したモデル専用に、RMVPEの隙間埋め版を選べるようにする（未実装）

  2はV/UVありで学習したモデルに使うと、子音が濁るので悪化する見込みです。

### 5.6 隙間ありで学習したモデルでも同じか（2170e）

**対象モデル**：`naru_20260906_kushinada_hubert_large_test1_2170e`。
HiFi-GAN、kushinada-hubert-largeで、学習F0は有声/無声を分ける方式です（発話中の有声率94.8%、切り替えは毎秒4.5回）。
設定はテンプレートと同じく index 0.592、protect 0、ブロック960 ms、extra 0.22 s、ピッチ0です。

realtimeで出力に使われたF0を、全体を見たF0と比べました。

| 方式 | 有声/無声の不一致 | cent差の中央値 | 50 cent超 |
|---|---:|---:|---:|
| mangio-crepe-full-speech | 0.6% | 6.8 | 1.3% |
| hpa-rmvpe-112000-aligned | 9.1% | 14.6 | 10.5% |
| rmvpe | 5.6% | 14.5 | 10.2% |
| fcn-993-rvc（0.3/0/3、Balanced v1とも） | 0.0% | 0.0 | 0.0% |

聞き比べ（ユーザーの聴感）：

- 隙間を埋めたもの（B相当）は、どの方式でも埋めないものより良く聞こえた。
- 埋めたものの中では **rmvpe > hpa-rmvpe-112000-aligned > mangio-crepe-full-speech**（学習に使った方式が最下位）。
- FCNでも、隙間あり（Balanced v1）は、常に有声（0.3/0/3）より悪く聞こえた。

分かったことと、分かっていないこと：

- **発話中の無声の隙間は、学習F0の種類によらず明瞭さを下げます。** 隙間ありで学習したモデルでも同じでした。
- 無声フレームでは、次の3つが同時に切り替わります（コードで確認済み）。
  - デコーダーの音源：振幅0.1の正弦波から、標準偏差約0.033の雑音だけになる（`sine_amp / 3`）
  - ピッチ埋め込み：無声の番号（1）になる
  - protect 0の場合：内容の特徴量が、indexで置き換えたものから元の声のものに戻る
- 3つのどれが効いているかは未確定です。protect 0.5のrmvpe（隙間あり）を作ってあり、聴感で確かめられます。
- 埋めた後の順位（rmvpe > hpa > mangio）の理由は分かっていません。次の3つは測ったうえで否定されました。
  - realtimeでのF0の崩れ：mangioが最も崩れていないのに最下位
  - mangioのF0が20 cent刻みの階段になっている：格子に乗るフレームは5.7%で偶然と同程度
  - 隙間の両端のF0の乱れ：中央値58〜67 centで差なし

### 5.7 隙間埋め版（`-filled`）

5.3のBと同じ処理を、F0方式として選べるようにしたものです。
元の方式のF0の無声フレームを、前後の有声フレームの対数補間で埋め、先頭と末尾は最寄りの有声フレームの値で延ばします
（`rvc/lib/predictors/f0_gap_fill.py`）。

| 方式 | UIの表示 | 元の方式 |
|---|---|---|
| `rmvpe-filled` | RMVPE (gaps filled) | rmvpe |
| `hpa-rmvpe-76000-aligned-filled` | HPA-RMVPE (76000, aligned, gaps filled) | hpa-rmvpe-76000-aligned |
| `hpa-rmvpe-112000-aligned-filled` | HPA-RMVPE (112000, aligned, gaps filled) | hpa-rmvpe-112000-aligned |

HPA-RMVPEの隙間埋め版は、元の方式の遅れ補正（aligned）と重みをそのまま使います。
学習抽出の記録には、元の方式の重みのSHA-256が入ります。
ほかの方式を追加するときは、`f0_methods.GAP_FILLED_METHODS` に「隙間埋め版 → 元の方式」を足し、元の方式の分岐を
`gap_filled_base(...)` で判定するようにします。

- 通常推論、batch、TTS、realtime、学習抽出、F0ツール、CLIで使えます。
- realtimeでは窓ごとに計算し直し、窓の中の隙間を埋めます。
- 学習抽出では、`rmvpe` で抽出済みのF0を再利用せず、抽出し直します。
- protectは無声フレームにしか効かないので、この方式では実質的に無効になります。
- 有声/無声の手がかりがなくなるので、隙間ありで学習したモデルの子音が濁る可能性は理屈の上では残ります。
  ただし、5.6の聞き比べでは、そのようなモデルでも良く聞こえました。

## 6. RMVPE以降の論文調査

「RMVPEより上で、RVCに組み込む価値があるもの」を探した結果です（2026-09-29時点）。
RMVPEを同じ条件で直接比べて、明確に上回ったと示した論文は見つかりませんでした。

| 手法 | 主張 | RMVPEとの関係 | 重み | RVCへの適性 |
