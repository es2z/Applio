# FCN-993 / FCN-993-RVC

## まず使うには（JSONは不要）

**FCNでRVC変換・学習抽出をする場合は、FCN-993-RVCを標準の選択肢として推奨します。**
原推定結果を比較したい場合には、V/UV判定を加えないFCN-993を使います。
これはFCN二方式の使い分けであり、あらゆる音声で他のF0方式より高精度という意味ではありません。

1. アプリを再起動します。
2. Pitch extraction algorithmで **FCN-993-RVC** を選びます。
3. **FCN profile JSON or local JSON path (optional) は空欄のまま**にします。
4. 通常どおり変換・抽出・realtime開始を実行します。学習抽出ではGPU番号を指定します。

対応するcheckpointにFCN設定が保存されていればそれを使い、なければ
同梱の **Balanced v1** を自動適用します。自分で閾値を決める必要はありません。

**保存済みcheckpointの設定に関係なくBalanced v1を使う場合**は、
「Load recommended FCN settings」を押してください。
現在の選択methodの推奨設定がJSON欄へ入り、その内容が優先されます。
FCN-993を選んで押した場合は、baseline用の設定が入ります。

CUDA上のPyTorch実装で、学習抽出、通常／batch推論、TTSのRVC変換、
realtime、F0 utilityが同じ設定を使用します。実行時のTensorFlowは不要です。

## 同梱する代表設定：Balanced v1

ファイル：[rvc-balanced-v1.json](../rvc/lib/predictors/fcn/profiles/rvc-balanced-v1.json)

- 有声化開始：confidence **0.50以上**
- 有声維持：confidence **0.40以上**かつ有効pitch候補あり
- native confidence／pitch median：**5 ms**
- 10 ms出力：有声候補のcents上のconfidence加重median
- UVのpitch持越し・gap補間：なし
- coarse範囲：50–1680 Hz
- torch.compile：OFF

同一network・weightに対してV/UV判定と短い時間処理を加えた、
RVC向けの標準構成です。baselineのように無音にも常にpitchを与える使い方を避けます。
confidenceはnetworkの最大activationであり、正答確率ではありません。

## そのまま使えるJSON

JSONを指定するのは、設定を明示して保存したい場合や調整したい場合だけです。
以下がBalanced v1の**完全な内容**です。そのままJSON欄へ貼り付けられます。

~~~json
{
  "method": "fcn-993-rvc",
  "version": 1,
  "enter_threshold": 0.5,
  "exit_threshold": 0.4,
  "median_frames": 5,
  "coarse_min": 50.0,
  "coarse_max": 1680.0,
  "calibrated": false,
  "compile_model": false,
  "compile_mode": "default"
}
~~~

または、この内容をUTF-8で例えばC:\dev\myapplio2\fcn-rvc.jsonに保存し、
JSON欄にそのファイルのパスだけを入力します。
同梱ファイルのパスを直接入力しても同じです：

~~~text
C:\dev\myapplio2\rvc\lib\predictors\fcn\profiles\rvc-balanced-v1.json
~~~

JSONにはコメントを入れず、文字列を半角のダブルクォートで囲みます。
ファイル全体を引用符で囲む必要はありません。

### 各項目の意味

| 項目 | 標準値 | 意味・変更の目安 |
| --- | --- | --- |
| method | "fcn-993-rvc" | UIで選択したmethodと一致させます。 |
| version | 1 | JSON形式のversion。変更しません。preset名のv1とは別です。 |
| enter_threshold | 0.5 | 無声→有声の開始閾値。高いほど新たな誤有声化を抑えます。 |
| exit_threshold | 0.4 | 有声を維持する閾値。低いほど弱声・語尾を残しますが、息への延長も増え得ます。 |
| median_frames | 5 | native 1 ms単位の窓長。5は5 msであり50 msではありません。0／3／5／9を指定できます。 |
| coarse_min | 50.0 | 量子化下限。現在は50固定です。 |
| coarse_max | 1680.0 | 学習モデルの量子化仕様。1680または1100。FCNの検出上限を変える設定ではありません。 |
| calibrated | false | 広範な話者分離校正・聴感評価の完了を宣言する記録用項目。実行のON/OFFや実験モードではなく、falseでも通常利用できます。変更不要です。 |
| compile_model | false | networkの任意compile。最初はfalseを推奨します。 |
| compile_mode | "default" | compile時のみ使用。default／reduce-overhead／max-autotune。 |

enter／exitは0〜1、exit <= enterが必要です。
明示JSONではmethod、enter_threshold、exit_thresholdが必須です。
その他の省略値はFCNProfileの値になるため、**Balanced v1と同一にしたい場合は上の完全なJSONを使ってください**。
特にmedian_framesを省略した明示JSONは0（OFF）です。
空欄は「未完成JSON」とは異なり、checkpointまたは同梱設定を選びます。

### 音を聞きながら調整する場合

まず上のJSONを使い、必要な場合だけ一項目ずつ変更します。

- **語尾・弱声が切れる**：exit_thresholdを0.40→0.35へ下げます。
- **声の立ち上がりを拾いにくい**：enter_thresholdを0.50→0.45へ下げます。
- **無声音に音程が付く**：enter_thresholdを0.50→0.60へ上げます。
- **発声後の息にも音程が残る**：exit_thresholdを0.40→0.45へ上げます。
- **素早いpitch変化が丸くなりすぎる**：median_framesを5→3へ下げます。

これらは調整方向の例です。複数値を一度に変えず、同じ音声で確認してください。
学習抽出の設定を変更すると再抽出されます。realtimeでは停止してから再開始します。

## CLIでの使い方

通常は --fcn_profile を指定しません：

~~~powershell
.\env\python.exe core.py extract --model_name MODEL --f0_method fcn-993-rvc --gpu 0 --cpu_cores 4 --sample_rate 48000 --include_mutes 0 --embedder_model japanese-hubert-base
.\env\python.exe core.py infer --input_path input.wav --output_path output.wav --pth_path MODEL.pth --index_path "" --f0_method fcn-993-rvc --embedder_model japanese-hubert-base
~~~

明示したい場合は、同じコマンドに次を追加します：

~~~powershell
--fcn_profile "C:\dev\myapplio2\rvc\lib\predictors\fcn\profiles\rvc-balanced-v1.json"
~~~

embedderは使用するcheckpointに合わせます。
infer／batch_infer／tts／extractで同じ --fcn_profile を使用できます。
優先順位は **明示JSON → methodが一致するcheckpoint設定 → 同梱設定** です。
methodを自動的に変更しません。baselineの同梱設定にはconfidence閾値を加えません。

各処理開始時に解決済み設定を固定します。学習workerやbatchの各音声が
実行途中で設定ファイルを読み直すことはありません。
checkpointへ具体的な値を保存するため、将来presetが追加されても
そのcheckpointの設定を暗黙に新しい値へ置換しません。

## 標準値を選んだ根拠と適用範囲

原repository付属のmanual例4／5／11／28と、
[手動修正済みF0の説明](https://github.com/ardaillon/FCN-f0/blob/8a2b530af821319b6badca93c8a0ed1f14bfee3c/examples/DTB/manual/f0_corrected/infos.txt)
を使い、複数の閾値を比較しました。計1,283 frames（10 ms単位）、
参照有声804 frames、参照無声479 framesです。

| 設定 | 無声を有声としたframe | 有声を無声としたframe |
| --- | ---: | ---: |
| **Balanced v1：0.50 / 0.40、median 5 ms** | **66 / 479（13.8%）** | **20 / 804（2.5%）** |
| 以前の動作確認値：0.60 / 0.40、median 5 ms | 56 / 479（11.7%） | 28 / 804（3.5%） |
| 厳しい候補：0.80 / 0.65、median 5 ms | 4 / 479（0.8%） | 86 / 804（10.7%） |
| Mangio-CREPE-full-speech、Viterbi | 83 / 479（17.3%） | 18 / 804（2.2%） |

誤有声化だけを減らす設定では声の欠落が増えるため、
声を残す方向とのバランスを取り、0.50／0.40を標準にしました。
この小標本は開発用の確認であり、話者分離した独立testではありません。
全音声での優位性や、日本語・歌唱・雑音・弱声の包括的な品質保証とは区別します。

[比較結果JSON](fcn-993-rvc-default-evaluation.json)と
tools/evaluate_fcn_rvc_presets.pyで、source／weight hashと再現手順を確認できます。
SDIF読取は[SDIF仕様](https://sdif.sourceforge.net/standard/sdif-standard.html)に従います。

以前はJSON必須の実験機能としていましたが、現在は代表設定を同梱した通常の選択肢です。
広範な校正やblind聴感評価は今後も必要ですが、利用者に校正作業を要求する構成にはしていません。

## 処理・再現性

- 原FCN-993のvalid Conv/ReLU/Pool/BN順序、BN eps=0.001、
  993-sample受容野、native stride 8、486-bin sigmoidを維持。
- networkはFP32 eval。TF32・AMPをFCN経路で無効化。
- 16→8 kHzはresampy 0.4.3のkaiser_best係数。
  CUDA側でも原実装の左右tap加算順とfloat32への丸めを再現。
- 496-sample zero padding後、994-sample population mean/std。
  NumPyのpairwise sum順序と除算の丸めも再現。
  stdが正確に0の場合だけfloat32 epsilonを使用。
- baselineは外周wrap、RVC型はzero extension。
- argmax近傍±4 binsのactivation加重cents平均。bin 0は30 HzでありUVではない。
- baselineはnativeの10点おきに直接選択。長さ比による補間なし。
- 空入力／0 framesは空配列、NaN/Infはエラー。
  p_lenはlen(audio)//160以下。超過分には明示的な音声paddingが必要。
- network処理はcontext付きblock分割。推論owner内でnetworkを再利用し、
  baseline/RVC adapter間でもweightを共有。global network cacheは使わない。
- 通常推論では真の音声上でF0を確定してから合成用reflect paddingを追加。
  FCN選択時のsilence-based外部分割は使用せず、合成にはPipeline内部の分割を使います。
- F0 utilityはseconds / Hz / confidence / voicedをCSVに出力。
  既存extract_f0()のcents APIも維持。

model_info.jsonにmethod、profile、weight SHA-256、architecture、
resampler／normalization／decoder、grid、coarse仕様、fingerprintを保存します。
入力音声の内容hashも再利用条件に含めます。
method／profile／重み／入力が変わればF0を再抽出します。

書換え前にrunを未完了にし、全worker成功とFCNの両F0ファイルの長さ・値を
確認してから完了metadataを確定します。途中失敗は親processとCLIへ伝播します。
未完了runからの学習開始／checkpoint出力を拒否します。
完了したprofileと量子化仕様はRVC checkpointへ引き継ぎます。
抽出失敗時にCLIが成功exit codeを返していた経路も修正しています。

## Realtime

session所有のFCNStreamとcapture resamplerが絶対sample clock、filter phase、
有限context、確定済みframe、hysteresis状態を保持します。
48→16 kHzのcapture resamplingもblockごとに独立したzero paddingを入れません。

確定したF0と同一時刻の音声windowをHuBERT／RVCへ渡します。
F0だけを過去へずらす処理ではありません。
waveform、前処理、networkはCUDAに保持し、既存pitch補正が必要な100 Hz配列だけ
NumPy境界へ渡します。

- 基本holdbackはbaseline／median 5までで140 ms。
  median 9では150 ms。capture filtering約0.46 msと最大10 msのgrid alignmentが加わります。
- 機器、chunk、queue、SOLA等を含む総遅延とは別です。
  UIには処理時間とFCN holdbackを分けて表示。
- warm-up後、capture overflow、再接続でstreamをreset。
  silence中もsample clockとvoicing stateを進め、弱声の尾を即座に切らない構成。
- FCNStream.flush()は終端paddingで残りframeを確定。
  live停止では機器を閉じるため、保留音声を停止後に再生しません。
- **baseline開始端の例外**：原wrapは音声末尾に依存するため、
  realtimeの最初のframeにはzero extensionを使います。
  この例外を内部chunk境界へ適用しません。
  RVC型は開始端もofflineと同じzero extensionです。

## 任意compile

profileにcompile_model: trueを指定するとnetworkだけをcompileします。
compile_modeはdefault、reduce-overhead、max-autotune。
既定OFFで、既存CREPEのglobal compile設定には連動しません。

新しい入力shapeの初回にactivation、復号pitch、argmax、
RVC型のraw confidence閾値判定をeagerと比較します。
実行例外／数値不一致では同じsessionのeager networkへ戻し、
stream stateをresetしません。
初回shape検証は全入力・全profileでのmask同値保証ではないため、
未検証profileではeagerを基準に比較してください。
速度改善を確認していない設定を推奨defaultにはしません。

## CUDA検証結果（2026-09-22）

環境：RTX 4090、PyTorch 2.13.0+cu132。
参照：隔離TensorFlow CPU 2.18.0／Keras 3.15.1、oneDNN OFF。
原HDF5をConv2D/BNへ直接読み込んで比較しました。
旧optimizerとtraining専用flatten/reshapeのみ省略しています。

前回の中間層不一致は次の切り分けで解決しました。

1. 同一float32 weightを双方でfloat64へ拡張して全層比較。
   993、1000、1001、8001、16001 samplesで厳しい1e-9基準を通過し、
   最大差は約3.84e-13。layout／architectureの一致を確認。
2. 実運用FP32では最終activationのatol=1e-5、rtol=1e-4と
   復号差0.1 centの基準を維持。中間層の丸め差は診断として記録。
3. 16 kHz入力→CUDA前処理→block network→独立した原cents復号との比較でも
   正弦、倍音、noise、impulse、DC、silence、微小振幅の全7波形が通過。
   最大activation差8.65e-7未満、最大pitch差約0.00134 cent。

これはFP32の全中間層が同じ1e-5基準で一致したという主張ではありません。
validation toolの既定all_layers gateと旧不合格reportを残し、
float64 audit後の --output-gate を明示的に使っています。

| 測定 | 結果 |
| --- | --- |
| F0 streaming、30分相当、8192-sample chunks | 180,000 frames、drift 0、p95 19.3 ms、締切超過0 |
| F0 streaming、1時間相当、8191-sample奇数chunks | 360,000 frames、drift 0、p95 20.0 ms、締切超過0 |
| 同1時間測定の最大保持音声 | 4,799 samples |
| 同1時間測定のGPU最大allocated memory | 約95.7 MB |
| 既存HiFi-GAN＋日本語HuBERTによるrealtime smoke | 512 msブロック、warm時約42–46 ms |
| 任意compile smoke | 実行成功、eagerとの差約0.00062 cent |
| CLI学習抽出・method切替・再実行 | 初回とmethod変更で再抽出、同一設定再実行は再利用 |
| UI | 学習／通常／batch／TTS／realtime／utilityの構築成功 |

長時間測定は合成波形を最速で処理するF0単体の試験です。
実機で1時間待った測定、マイク／queueの耐久試験、聴感評価ではありません。
RVC smokeにも合成入力と実験用RVC閾値を使用しており、
音声品質や閾値校正の根拠にはしていません。

reportはrvc/lib/predictors/fcn/内のparity-*、benchmark-*、smoke-* JSONに保存。
新規テストに加え、既存CREPE、extract compile、realtime compile、
silence/seed、embedder関連を含む168件のテストが通過しています。
学習開始を妨げていた既存のpretrained selector呼出も、現行の2引数APIに修正しました。

## 検証・校正ツール

- tools/convert_fcn993.py：ネットワーク取得なしのHDF5変換。
- tools/validate_fcn993.py：fixtures生成、隔離TF oracle、全層／最終出力／waveform比較。
- tools/benchmark_fcn_f0.py：CUDA streamの処理時間、buffer、memory、時刻drift。
- tools/calibrate_fcn993.py：話者分離したcalibration/validation/test NPZから、
  0.01刻みのenter/exit、median 0/3/5/9を探索。
  validationでMangio以下のUV→V誤判定を満たす候補から
  弱声のV→UV、全有声音のV→UV、hysteresis幅、窓長の順に選択。
  held-out testを通ってもcalibrated:falseの候補として保存。
  聴感評価の結果を自動で捏造しません。
- tools/fcn_viterbi_reference.py：比較専用の486-state categorical Viterbi。
  同じ最適scoreのpathはhmmlearnと異なるtieを選び得るため、
  hmmlearn 0.3.3との検証では最適log probabilityも比較。
  runtime defaultやrealtimeには使用しません。

校正NPZの必須項目と時刻単位はcalibrate_fcn993.pyの冒頭に記載。
原repositoryの注釈付き4例で比較したBalanced v1を同梱しています。
広範な話者分離校正・blind聴感評価まで完了したという意味ではありません。
Python 3.13環境での実行と、量子化・realtimeが異なる外部checkpoint群での
広範な聴感比較も未検証です。
