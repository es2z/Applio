# 新しいリアルタイム設定と「今までの声」に戻す方法

対象はブランチ `realtime-latency-quality` で増えた設定だけです（Realtime タブ > Performance Settings >
「遅延・音質の実験的オプション」）。設定はすべて Start 時に反映されるので、変えたら Stop → Start します。

## 1. 今までと同じ声にするには

**下の表の「今までと同じ値」に全部そろえてください。** その状態なら、変換の計算は今までと同じです。
CPU で変更前の main と出力を比べ、ビット単位で一致することを確認しています。実モデル・GPU・
torch.compile の組み合わせではまだ比べていません。

Start 後のステータスで確かめられます。

```
Options: legacy | window delay 370 ms
```

- `Options:` の後が `legacy` なら、新しい設定は全部「今までと同じ値」です。
- 名前が並んでいたら（例: `Options: output_position, apex_noise_envelope`）、それが有効になっています。
- `window delay` は基準テンプレート（Chunk 960 ms / Crossfade 0.138 s / Extra 0.22 s）なら 370 ms です。
  150 ms 前後なら「出力位置」が trim になっています。

テンプレートを読み込むと、保存されていた新しい設定も一緒に入ります。このブランチより前に保存した
テンプレートには新しい設定が無いので、読み込むと全部「今までと同じ値」になります。

## 2. 新しい設定の一覧

「声への影響」は、オンにしたときに予想される変化です。耳での確認はまだしていません。

| 画面の名前 | 今までと同じ値 | 選べる値 | 声への影響 |
|---|---|---|---|
| 出力位置 | **legacy** | legacy / trim | trim は遅延が約 0.22 秒減る。再生する部分が参照できる「先の音声」が約 220 ms から Crossfade 分に減り、語尾や立ち上がりが変わり得る |
| 先読み (秒) | **0** | 0〜0.3 | trim のときだけ有効。増やすと trim の変化が小さくなる代わりに、遅延が同じだけ増える |
| 入力の 48 kHz → 16 kHz 変換 | **stateless** | stateless / stateful | ほぼ無し。ブロックの境目の小さな不連続が消える |
| Protect が使う有声判定 | **f0** | f0 / unfilled | Protect が 0.5 のときは何も変わらない。0.5 未満なら、子音や息が元の声寄りになる |
| 出力ゲイン | **legacy** | legacy / aligned | 強弱のつき方が変わる（音量が入力の動きに時間どおり付いてくる） |
| APEX-GAN ノイズ包絡 | **window** | window / fixed | fixed は有声部のノイズが今の約 1/3〜1/6 になる。息っぽさ・ざらつき・空気感が減り、乾いた声になる見込み |
| 学習データの有声率 | **0.65**（どの値でも同じ） | 0〜1 | fixed のときだけ使う。大きいほどノイズが多く、1.0 で window とほぼ同じ量（F0 が穴埋めありの場合） |
| オーディオ転送方式 | **legacy** | legacy / ring | 声は変わらない。遅延が約 0.9 秒減る見込み。予備の調整で、-60 dBFS 未満の静かな部分だけ数 ms 詰めたり伸ばしたりする |
| ring 方式のストリーム | **auto**（どの値でも同じ） | auto / separate | ring のときだけ使う。separate は出力を可変レートで変換する（21 kHz まで平坦） |
| ノイズを時刻に固定 | **オフ** | オン / オフ | ブロックごとのノイズの引き直しが無くなる。揺らぎが減って均一に聞こえる可能性がある |
| 正弦波の位相を連続させる (APEX-GAN) | **オフ** | オン / オフ | つなぎ目の位相のずれが無くなる |
| F0 キャッシュ | **オフ** | オン / オフ | F0 を、先の音声をマージン分しか見ずに確定する。抑揚がなまる可能性がある。出力位置 legacy と組み合わせると特に不利 |
| F0 キャッシュのマージン (ms) | **100**（どの値でも同じ） | 0〜300 | F0 キャッシュのときだけ使う |
| 潜在ノイズの温度（P1） | **0.67** | 0〜1 | 下げると揺らぎが減って安定する代わりに、平板に聞こえやすい |
| 入力のハイパス（Hz、IO1） | **0** | 0〜120 | 48 なら声の帯域はほぼ変わらない（100 Hz で 0.01 dB 未満）。80 以上で低い声の基音が少し下がる |
| 出力をクリップする位置（IO4） | **generator** | generator / output | 生成器の出力が 0 dBFS を超えないなら変わらない。超えるかはステータスの `Level:` 行で分かる |
| 無音ゲートが閉じるときのフェード（ms、IO5） | **0** | 0〜100 | 話し終わりの最後の数十 ms だけ。切れ方が滑らかになる |
| 無音のあいだゲートを閉じたままにする（IO5） | **オフ** | オン / オフ | 無音のあいだだけ。周期的に漏れる小さな雑音が止まる |

ステータスの `Level:` 行（生成器と出力のピーク）は表示だけで、音は変えません。

## 3. 「そっけなくなった」と感じたときに疑う順

`Options:` に名前が出ている場合は、次の順に 1 つずつ「今までと同じ値」に戻して聴き比べてください。
上ほど、声を乾いた・平板な方向に変える可能性が高いと考えています。

1. **APEX-GAN ノイズ包絡 = fixed**: 有声部のノイズが大きく減る。学習時に近い量ではありますが、
   今まで聴いてきた声は window の方です。最有力です。fixed のまま「学習データの有声率」を 1.0 に
   近づけると、今までの量に近づきます（0.65 と 1.0 の間で好みの量を探せます）。
2. **潜在ノイズの温度 < 0.67**: 揺らぎが減る。
3. **F0 キャッシュ = オン**: 抑揚がなまる可能性。
4. **出力位置 = trim（先読み 0）**: 語尾や立ち上がり。先読み 0.1 で変化が小さくなるかを確かめる。
5. **出力ゲイン = aligned**: 強弱のつき方。
6. **ノイズを時刻に固定 / 位相を連続させる**: 揺らぎが均一になる。
7. **Protect が使う有声判定 = unfilled**（Protect が 0.5 未満のときだけ）。

オフラインの比較ツール（`tools/realtime_stream_eval.py`）は、`--preset` を付けないと `legacy` と
`stage1` の 2 つを書き出します。`stage1` は「出力位置 trim、入力 stateful、出力ゲイン aligned」で、
今までの声ではありません。今までの声は `__legacy.wav` の方です。

## 4. `Options: legacy` なのに声が違うとき

新しい設定以外の原因を順に確かめます。

1. **RNG シード**: 「RNG Seed」が -1（ランダム）だと、Start のたびにノイズが変わり、声の印象も
   変わります。`rvc/realtime/rng.py` の記録では、シードを固定しない 2 回の実行の差は、通常推論と
   torch.compile の差より大きいほどです。比べるときは同じシード値（例: 1234）にしてください。
2. **ほかの設定**: 出力デバイス（WDM-KS か WASAPI か）、テンプレート、Chunk、F0 の手法、
   Index Rate、Protect、embedder の精度などが、前と同じかを確かめてください。このブランチは
   `assets/config.json` を変更していません。
3. **main と直接比べる**: `git checkout main` で戻し、同じテンプレート・同じシード・同じ入力
   （録音を仮想ケーブルで流すのが確実）で聴き比べます。終わったら
   `git checkout realtime-latency-quality` で戻します。
   - それでも違うなら、このブランチの不具合の可能性があります。コミットごとに戻して
     （`5b8cf9b` → `474bc1c` → `d076ba7` → `ac3ec1b`）、どこで変わるかを確かめてください。
     ローカルの Claude Code に頼む場合は、この節と `docs/HANDOFF-realtime-latency-quality.md` を
     渡してください。

## 5. 声を変えずに試しやすいもの

今の声を保ったまま遅延や雑音だけを改善したい場合は、声への影響が小さいものから試してください。

| 設定 | 期待できること | 声への影響 |
|---|---|---|
| オーディオ転送方式 = ring（入出力が別の機器なら ring 方式のストリーム = separate） | 遅延 約 −0.9 秒（見込み） | 無し（静かな部分の予備調整だけ） |
| 無音ゲートのフェード 30 ms と、無音のあいだゲートを閉じたままにする | 話し終わりと無音中の小さな雑音 | 話していない部分だけ |
| 入力の 48 kHz → 16 kHz 変換 = stateful | ブロックの境目の不連続 | ほぼ無し |
| 出力をクリップする位置 = output | 生成器が 0 dBFS を超える場合のひずみ | 超えなければ無し |

出力位置 trim は遅延の短縮が大きい代わりに、声が少し変わる可能性があります。試すなら先読みを 0.1 秒から
始め、変化が無いことを確かめてから減らしてください（先読み 0.1 なら遅延の短縮は約 0.12 秒）。
